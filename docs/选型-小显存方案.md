# 选型报告：小显存机器跑 VRChat 实时同传（2026-11）

> 目标不变：A 链「我说话 → 对方听到日语」、B 链「对方说话 → 我中文字幕」、C 链「屏幕文字 → 中文浮在原位」，延迟理想 1 s、上限 2–3 s，音色要像本人。
> 本文按「**显存很小 + 同一台机器还要跑 VRChat**」重做选型。不假设本机配置，只按显存档位（0 / 4 / 6 / 8 / 12 / 16 GB）给方案。

---

## 0. 一句话结论

**小显存机器的正解不是「找更小的模型」，而是「把模型搬出显存」**：ASR 交给 CPU（SenseVoice 一个二进制，零显存）、MT 和 TTS 交给云（套餐端点，零显存）、OCR 本来就在 CPU（几十 MB）。这样显存占用 **0 MB**，A 链还能压到 1.0–1.6 s，比在 4 GB 卡上硬塞本地模型（2.5–4 s 且掉帧）快一倍、质量高一档。

只有两种例外值得上 GPU，且都要 12 GB 以上卡：① 想省云费，把 MT 换成本地 Index-Translate-2B（2.7 GB）；② 想离线，把 TTS 换成 CosyVoice2-0.5B（1.6 GB）。

---

## 1. 先把「目的」翻译成选型指标

三链对模型的要求完全不同，不能一把尺子量：

| 链 | 用户感知的东西 | 真正决定体验的指标 | 可以牺牲的 |
|---|---|---|---|
| A 我说话 → 日语出声 | 对方觉得「这人日语说得自然」 | **TTS 音色相似度 + 韵律自然度**；端到端延迟 < 1.5 s | ASR 可以用小的（我说的是中文，识别不难） |
| B 对方说话 → 中文字幕 | 我看得懂 | **ASR 准确率（远场/唱歌/多人/口音）** + MT 质量 | 延迟 1–2 s 完全能忍 |
| C 屏幕文字 → 中文 | 我看得懂 | OCR 小字/花字/竖排准确率 | 帧率（300 ms 一帧够了） |

据此排优先级：**TTS 质量 > ASR 准确率 > MT 质量 > 一切延迟**。这直接推出「TTS 绝不能降级到本地小模型」——那是用户唯一会被人当场听出来的环节。

---

## 2. 显存到底还剩多少

VRChat 自身占用（社区实测，2026）：人多 / 高画质世界里 **VRAM 约 7.8 GB + 内存约 13.7 GB**（合计 21.5 GB）；VRAM 到 9.3 GB 时 8 GB 的 3070 会被 12 GB 的 3060 反超。日文装机指南 2026 版的结论是「**为 VRChat 买卡，8 GB 以下不要考虑，12 GB 起步**」。

换算成「留给我们模型的空间」（要留 1–1.5 GB 给驱动/浏览器/编码器抖动）：

| 朋友的卡 | VRChat 实际吃 | 安全留给模型 | 结论 |
|---|---|---|---|
| 核显 / 4 GB | 已爆显存走共享内存 | **0** | 只能全云或 CPU |
| 6 GB | 5–6 GB | **0** | 只能全云或 CPU |
| 8 GB | 5.5–7.5 GB | 0–0.8 GB | 基本只能全云；本地最多塞 CosyVoice2-0.5B（还会掉帧） |
| 12 GB | 7–8.5 GB | 2.5–4 GB | 可上本地 MT（Index-Translate-2B INT8） |
| 16 GB | 8–10 GB | 5–7 GB | 可上 Hunyuan-MT-7B Q4 或 IndexTTS-2（6 GB） |

**关键结论**：在 8 GB 及以下，「本地模型」这条路不是慢，是**会把 VRChat 挤到掉帧/卡顿**——玩家会立刻感觉到。所以下面所有方案的默认答案都是「不占显存」。

### 3.4 一体化「语音到语音」（为什么不用）

| 模型 | 显存 | 结论 |
|---|---|---|
| Step-Audio-2-mini (8B) | **20–25 GB**（ASR 模式 20–25 GB，S2ST 单卡 40–50 GB） | ❌ |
| Voxtral-Mini-3B | 9.5 GB | ❌ |
| Qwen3-Omni-30B-A3B | 30B MoE，远超 | ❌ |
| MiniCPM-o-4.5 (9B) | ~18 GB | ❌ |
| Moshi / SeamlessM4T v2 | 中 | 延迟好，但**不可编辑、不给中间文本** |

**结构性理由**：VRChat 场景不只要声音，还要 ① chatbox 文本、② 自己的中文字幕、③ 定点语种（永远 ja，不能自作主张换语言）、④ 术语表（地图名/角色名）。一体化 S2S 把这四样全丢了。所以**链路式（ASR→MT→TTS）是唯一正确架构**，模型再强也不换。

### 3.5 OCR（C 链）

RapidOCR：PP-OCRv4 det（736 边长）+ japan_rec，**CPU，约 50–80 MB，60–120 ms/帧**。任何一个方案都本地跑，不参与选型权衡。

### 3.7 qwen-audio-3.0-realtime-plus（套餐里藏着的王牌）

官方文档摘录（2026-11-06 版，实测抓取）：

| 项 | 值 |
|---|---|
| 定位 | 实时**双工语音**大模型，Artificial Analysis Speech-to-Speech 子项**综合第一** |
| 输入 / 输出 | Audio + Text / **Audio + Text**（同一路既出声音又出文本） |
| 上下文 | 40960（输入上限 16384 / 输出 8192 / 思维链 1024） |
| 工程 | 并行推理 + 全向流式，「端到端响应时延控制在低水平」 |
| 价格（华北2） | 输入音频 40 元/百万 token、输入文本 5、输出文本 40、**输出文本+音频 150 元/百万 token**（输出文本不重复计费） |
| 限流 | RPM 60 / TPM 100,000 |
| 不支持 | Function Calling、结构化输出、前缀续写、上下文缓存、批量推理 |

**对本项目的意义**：A 链可以做成「我说话 → 它直接出日语语音 + 日语文本」的**一跳**，省掉 ASR→MT→TTS 三段排队，延迟与韵律双赢，且**零显存**。风险是太"自由"：它可能不按你要的语种/术语说话。所以定位是 **P0-Alt（可选项，值得花两小时实测）**，不是默认。

## 4. 六套方案


> 延迟预算写法：VAD 收尾 + ASR + MT + TTS 首包 + 播放启动。VAD 收尾可用 `end_silence` 从 0.50 压到 0.35（代价：偶尔截断）。

### P0 全云（**推荐默认**）：零显存，最快落地

- ASR：qwen3-asr-flash-realtime（流式增量）；兜底用现成的 qwen-audio-3.0-asr-flash
- MT：qwen3.6-flash / qwen-mt-turbo
- TTS：qwen-audio-3.0-tts-plus（音色 t3 克隆）
- OCR：本地 CPU
- **显存 0 MB / 内存 ~0.4 GB**
- **A 链 1.0–1.4 s**（0.35 + 0.25 + 0.30 + 0.80 + 0.05）；若 TTS 换 qwen3-tts-flash → **0.6–0.9 s**
- **B 链 0.5–0.9 s**（流式 ASR 边说边出，字幕比说话慢半句）
- 质量：**最高档**（音色、术语、日语自然度全是云端最强的那批）
- 成本：ASR $0.15/h 级 + MT 几毛 + TTS 按字符（一晚 4 h 约 **5–15 元**量级）
- 代价：断网即哑；需要能连 DashScope（国内端点可直连，不需要梯子）
- 落到本项目：`asr_engine_a/b = "cloud"`（或改流式适配器）、`mt_model`、`voice` 不变，**零新增依赖**

### P0-Alt 全云「一跳」：用 realtime-plus 直接语音到语音（**值得实测**）

- 一条 WebSocket：我说话（中文）→ 模型直接出**日语语音 + 日语文本**
- 显存 0；**A 链理论 0.4–0.8 s**（省掉 ASR 段排队 + MT 段 + TTS 段）
- 质量：韵律/情绪连贯性**优于** TTS 拼接（它不是"念译文"，是真的在说话），Text 输出可进 chatbox
- 代价：① 语种要靠 system prompt 钉死（要实测"永远说日语"稳不稳）；② 术语表只能塞进 prompt，不保证遵守；③ 输出侧要重新接一遍播放/duck/回声闸；④ 按 token 计费，重度用比 TTS 贵
- 落到本项目：新增 `vrdub/rt_link.py`（一条 WS、PCM 直灌、收 audio delta）+ A 链旁路开关 `a_mode = "split" | "s2s"`；B/C 链完全不动（B 链仍需要精确中文字幕，S2S 出的文本不够可靠）
- **建议做法**：先花两小时写个最小脚本，让它在 5 句中文上连说，听日语是否稳定、术语是否乱。稳就上，不稳就留在 split。

### P1 云 TTS + 云 MT + **CPU 本地 ASR**：零显存，抗抖动

- ASR：SenseVoiceSmall GGUF（CPU，单文件二进制，自带 VAD）
- MT / TTS：同 P0
- 显存 0；CPU 多占 1 核 / 0.6 GB
- **A 链 1.0–1.3 s**（ASR 0.10–0.35 且**没有云抖动**，比全云更稳）
- **B 链 0.4–0.8 s**（本地 143–351 ms + 后台云端校正字幕）
- 质量：识别略低于云端（本项目实测 5 条日语素材文本相似度 1.00，实际差距很小），TTS 不变 → **听感无损**
- 成本：比 P0 再省 ASR 那部分
- **这是「小显存 + 同时玩 VRC」的最优组合**：显存 0、延迟稳、离线也能出字幕
- 落到本项目：就是现在的 `asr_engine_b = "hybrid"` 再往前一步（把 A 链也设 hybrid/local）

### P2 本地 MT（12 GB+ 卡）：省云费，慢一点点

- ASR：CPU SenseVoice
- MT：**Index-Translate-2B INT8（2.67 GB 显存）**
- TTS：云 qwen-audio-3.0-tts-plus
- 显存 2.7–3.2 GB（VRChat 8.5 GB + 此 3 GB ≈ 11.5 GB，**12 GB 卡刚够，16 GB 舒服**）
- A 链 1.3–1.9 s；B 链 0.9–1.5 s
- 质量：日常对话够用，**梗/地图名/角色名会翻错**（需喂术语表）；比云端 MT 差一档
- 适合：流量敏感 / 想少花钱 / 网络不稳

### P3 全本地（16 GB 卡，或 12 GB 卡不玩 VRC 时）

- ASR：SenseVoice CPU
- MT：Hunyuan-MT-7B Q4（4.5 GB）
- TTS：**CosyVoice2-0.5B（1.6 GB）** 3 s 克隆
- 显存 6–7 GB → 只能在没有 VRChat 或 VRChat 画质最低时跑
- A 链 1.5–2.5 s；B 链 1.0–1.8 s
- 质量：**日语音色明显不如云端**（跨语种克隆有口音残留），这是最大短板
- 适合：完全离线 / 隐私优先


### P3-实测补充：8 GB 卡上「本地大模型」到底值不值（2026-11 实测）

本机就是 8 GB 卡（RTX 5060 Laptop，VRChat 同时在跑，空闲 3.5 GB）：把 ASR 换成本地 anime-whisper（CTranslate2 int8_float16，1.1 GB 显存）实测，

| 引擎 | 干净 5 条 | 5 条 × 噪声5/混响/BGM/远场（20 组） | 单段耗时 | 显存 |
|---|---|---|---|---|
| 云端 qwen-audio-3.0-asr-flash | 1.000 | **1.000** | 1.4–5.2 s（最长 13.1 s） | 0 |
| 本地 SenseVoice int8（CPU） | 1.000 | **0.992** | 0.25–0.32 s | 0 |
| 本地 anime-whisper int8_float16（CUDA） | 0.975 | 0.968 | 0.31–0.35 s | 1.1 GB |

**结论**：8 GB 卡 + VRChat 同跑时，本地动漫 whisper 的价值是「**离线可用 + 带标点**」，不是「更准」——它比 SenseVoice 低 2–3 个百分点，还多吃 1.1 GB；而 CPU 上它根本不可用（4 s 音频 10.5–26.5 s，ct2 int8 在这颗 i7-14650HX 上只有 ~55 GFLOPS 有效算力）。所以正确用法是：**SenseVoice 当快路（零显存），精准度交给云端精修，本地 whisper 只当断网兜底**。想彻底不联网又要有标点，才值得让它常驻。

### P4 纯 CPU 全本地（核显/笔记本）

- ASR：SenseVoice GGUF（0.1–0.35 s）
- MT：TranslateGemma 4B Q4 走 CPU（llama.cpp，**2–5 s/句**）或 Index-Translate-2B int4 CPU（3–6 s）
- TTS：Kokoro-82M（CPU，126 ms，**音色不是本人**）
- 显存 0；延迟 **4–8 s**，超出「上限 2–3 s」
- 结论：**只能当断网兜底**，不能当日常方案

### P5 双机分工（**显存最优 + 质量不减**）

- 主机：VRChat + 采集/播放 + OCR（几乎零开销）
- 副机（旧笔记本 / 迷你主机 / 甚至手机）：SenseVoice + MT 小模型
- 云：TTS（唯一必须联网的部分）
- 显存：主机 0、副机随意
- A 链 1.2–1.8 s（多一跳局域网 ~2 ms，可忽略）
- 适合：**主机是小显存但家里有第二台机器** —— 这是最省心的长期方案，等于把 P3 的算力搬到另一台机器

## 5. 决策树

```
朋友机器显存 <= 8 GB（要同时玩 VRChat）
├── 有稳定网络 ──> P1 CPU-ASR + 云（最稳，推荐）/ P0 全云（最省事）
│                  └ 想要「像真人说话」的韵律 ──> 先实测 P0-Alt（realtime-plus 一跳）
├── 网络差或有流量顾虑 ──> P5 双机（副机跑本地）+ 云 TTS
└── 必须离线 ──> P4（接受 4–8 s）或 P3（换 16 GB 卡）

朋友机器显存 >= 12 GB
├── 想省钱 ──> P2（本地 MT 2.7 GB）
└── 想离线 ──> P3（本地 TTS，接受音色掉一档）
```

## 6. 朋友机器上的落地清单（按 P1 走，30 分钟）

1. **装 VRChat 端**：虚拟音频线（VB-Cable）+ 本项目 `run.bat`；`%LOCALAPPDATA%\VRDub\config\settings.json` 里按他的设备号改 `mic_dev / out_dev / mon_dev`（用控制台「设备」页点一下就有号）。
2. **ASR 走 CPU**：`asr_engine_a = "hybrid"`、`asr_engine_b = "hybrid"`。本地模型用 `models/sensevoice/`（228 MB int8），已带 tokens.txt，不需要 CUDA。
3. **云侧**：`.env.local` 填 `DASHSCOPE_TOKENPLAN_KEY`（套餐端点 `token-plan.cn-beijing.maas.aliyuncs.com`）。TTS 音色先用自己的 3 s 样本克隆一次，拿到 `voice` id 填进 `cfg.voice`。
4. **压延迟**：`end_silence = 0.40`、`spec_silence = 0.18`、`live = True`、`presynth = True`。这四项就够从 1.6 s 压到 1.2 s。
5. **保质量**：`refine = True`（云端后台校正字幕，不计入延迟）、`card = "natural"`、术语表填他的常用角色名/地图名。
6. **别动的**：`echo_guard = True`（不然自己的日语会被翻译一遍）、`leak_gate / bleed_lvl = False`（B 链比麦克风响时必误杀）。

### 若要接流式 ASR（P0 的 1 s 档），本项目只改三处

- 新增 `vrdub/asr_rt.py`：WebSocket 接流式识别（套餐内没有 asr-flash-realtime，要用按量付费的 `qwen3-asr-flash-realtime` / `paraformer-realtime-v2`；套餐内的 `qwen-audio-3.0-realtime-plus` 走的是 P0-Alt 那条 S2S 路径），把 `input_audio_buffer.append` 的 PCM 帧从现有采集环直接灌进去，返回增量文本 → 复用现有 `bus.upd(..., state="partial")` 通道。
- `vrdub/chains.py` 的 A 链识别入口加一条：`if cfg["asr_engine_a"] == "rt": seg_text = self.rt.poll(t0)`。
- `cfg.py` 加 `"asr_engine_rt": False`、`"rt_url"`。其余（分句、投机识别、预合成、回声闸）全部不动。

## 7. 网络与代理（这条最容易翻车）

- **VRChat 别走全局代理**：VRChat 的语音是 UDP，全局梯子会造成语音断续、甚至进不去区服。正确做法是**只给需要用梯子的域名走代理**（系统代理 + 分流规则），VRChat 进程直连。
- **DashScope 用国内端点，直连即可**（`*.aliyuncs.com` 国内可访问），不需要梯子 —— 也就是说「VRChat 直连 + 云 API 直连」是可以共存的，梯子只用来查资料/下载模型。
- 如果朋友的云 API 走不通，退回 P1/P5：识别和 MT 全本地，只有 TTS 必须联网（也可以临时换成 Kokoro 兜底，牺牲音色）。

## 8. 风险与回退

| 风险 | 触发场景 | 回退 |
|---|---|---|
| 云端 ASR 抖动（0.67–2.9 s，长段十几秒） | 网络抖动 / 说话太长 | 走 hybrid：本地先出字幕，云端后台校正 |
| 显存被 VRChat 吃掉导致模型换出 | 8 GB 卡 + 人多世界 | 全方案改 CPU/云，显存占用归零 |
| 音色不像 | 本地 P3 | 换回云端 TTS（这是唯一不能妥协的一项） |
| 断网 | 云方案 | P1 本地 ASR 仍能出中文字幕；TTS 降级 Kokoro |
| 术语翻错 | 本地 MT | 加术语表 / 换云端 MT |
