# VRDUB 网页控制台 + 浮窗 · 使用说明

一套本地跑的实时语音转译工具，两块界面：**网页控制台**（所有设置、实时句子表、日志）和**桌面浮窗**（放在 VRChat 画面角落的字幕条）。

- 网页：`vrdub/web/index.html` + `app.js` + `style.css`（纯原生 HTML/CSS/JS，零外链、零框架，断网可用）
- 浮窗：`vrdub/hud.py`（PySide6，由后端作为子进程拉起，走 stdin 收数据）

截图：`out/web_live2.png`（**接真后端 127.0.0.1:8899 实拍** 1600×1000：18 句回环注入跑完后的句子表 + 非零延迟分解，C 卡是「未框选区域 · 已暂停」的告警态）、`out/web_inject.png`（同一后端，点「回环自测」后 A 链接住的实时行 + 闭麦徽章入镜）、`out/hud_shot.png`（浮窗实拍 1080×839）、`out/hud_drag.png`（拖到屏幕中段后的浮窗，1200×454，压在资源管理器与浏览器之上）、`out/danmaku_a.png` / `out/danmaku_b.png`（弹幕实拍，真实桌面 2560×1600）、`out/web_c_chain.png`（**2026-11-18 接真后端实拍** 1570×905：C 卡「按一下识别一帧」模式 + 提示行「识别到 1 行 · 111 ms」+ 右栏识别原文/译文，句子表里那条 C 链行带橙竖线）、`out/web_pick.png`（同一次点击「框选范围」→ 遮罩确认后的「框选完成 · 物理 1536×416（逻辑 1024×277）」）、`out/region_picker.png`（遮罩本体：全屏半透明 + 亮框 + 8 个白手柄 + 角落尺寸胶囊，底下是真实桌面 2560×1600）、`out/web_shot.png`（离线预览）、`out/web_http.png`（1400 宽）、`out/web_narrow.png`（1120 宽单列堆叠）、`out/web_live.png`（早期接联调桩的版本）。

## 一、怎么打开

**1. 正常用法（接后端）**
先让后端跑起来（默认 `127.0.0.1:8899`，端口被占会自动 +1），然后浏览器打开 `http://127.0.0.1:8899/` —— 后端把 `vrdub/web/index.html` 挂在 `/`，静态资源挂在 **`/static/`**（`/static/style.css`、`/static/app.js`）。页面里的资源加载是**双候选**：http(s) 下先要 `/static/xxx`，失败再退相对路径 `xxx`；`file://` 下只用相对路径。三种托管（真后端 / 双击本地文件 / `http.server`）都能跑，不会出现裸 HTML。
前端会自动重试 `/api/state`：先试当前域名，再试 `127.0.0.1:8899`、`8900`；拿到 `state.url` 后所有请求都以它为 base（所以端口加了 1 也能自己找到）。

**2. 只想看看界面（不接后端）**
直接双击 `vrdub/web/index.html` 用浏览器打开即可 —— 它会进入**离线预览**：右上角出现紫色「离线预览」标签，状态点变紫，句子表用内置假数据持续滚动，所有操作都只改本地显示、不会真发请求（日志里会写「离线预览：未发送」）。

**3. 不用后端、但要 http 环境**
```
python -m http.server 8911 --bind 127.0.0.1 --directory vrdub/web
```
访问 `http://127.0.0.1:8911/index.html`。没有后端时同样落到离线预览，日志里能看到三条「连不上」+「进入离线预览」。

**4. 浮窗**
后端托管时会自动拉起（`hud_on` 打开时）。手动看效果：
```
python tools/hud_feed.py --count 30 --hold 12 | python vrdub/hud.py
```
浮窗跑在屏幕**底部居中**：无边框、置顶、半透明、**默认可拖动**、不抢焦点；要穿透就右键它（再点右上角小把手取消）。

## 二、顶栏（一行看完状态）

| 元素 | 作用 |
| --- | --- |
| **开始转译 / 全部停止** | 一键把 A 链（出）+ B 链（入）同时开或同时关；紫色=停、绿色=在跑。只动这两条，C 链（屏幕）单独开关。 |
| 状态灯 + 文字 | 绿=已连上后端；黄=正在重连（SSE 断了 2 秒自动重试）；红=请求失败，同时把错误写进右下日志；紫=离线预览。旁边 ↻ 立即重新拉一次状态。 |
| **麦克风开 / 麦克风已闭** | 麦克风总闸（等价 CapsLock）。关掉后按钮变红、文字变「麦克风已闭」，并且顶栏出现红色脉冲徽章、浮窗右上角出现红「麦已闭」。 |
| **麦克风打不开**（红胶囊） | 后端 `state.mic.reason` 非空时出现，把后端原话打出来（例如 `麦克风打不开：OSError(-9999, 'Unknown error')`）。鼠标悬停看说明「A 链此时收不到声音」。**从不静默**——采不到音一定在界面上看得见。 |
| **延迟 P50**（大数字） | 端到端延迟中位数（毫秒）。超过 1800 变橙。 |
| **P90** | 端到端延迟 90 分位。超过 2400 变橙。 |
| B 链 P50·P90 | 对方声音那条链路的延迟，小字。 |
| **丢段** | 被后端丢弃（`state=drop/err`）的句子计数，>0 变红。 |
| 离线预览 | 仅演示模式出现。 |

## 三、左栏

**三条链 A/B/C**（点开关立即生效，不用保存）
- **A 出·我说的**（青色）：我说的话 → 识别 → 翻译 → 合成 → 送进「对方听到」的设备。左下拉=我听懂的语种（自动/中/日/英），右下拉=对方听到的语种。
- **B 入·对方说的**（紫色）：对方说话 → 识别 → 翻译 → 中文字幕给浮窗。左=对方说的语种，右=我看到的字幕语种。
- **C 屏·聊天框**（橙色）：截屏读聊天框文字 → 翻译 → 字幕贴回原位。纯拉丁名字（Aoi、Kira…）不再被当成生词乱翻，直通原文。卡里从上到下：**模式胶囊 → 语种/框选行 → 提示行 → 实时句 → 状态行**。
  - **两个模式胶囊**：「按一下识别一帧」（cfg.ocr_mode="hotkey"，默认，推荐）只在按 F6 或点「识别一帧」时抓一帧，不占 CPU；「常驻识别」（"poll"）是老用法，每 0.35 s 抓一帧、字幕自己冒出来。点胶囊立刻 POST /api/cfg {"ocr_mode":…}；选「常驻识别」时如果 C 链还关着，会顺手把它打开。
  - **「屏幕上 自动判断」**：cfg.ocr_src，自动判断 / 日语 / 英语 / 中文 / 韩语 / 俄语 / 其它（视觉抄字）。中日英走本地 OCR，其余走多模态抄字。
  - **「框选范围」**：全屏弹遮罩（等同全局热键 F5），拖出聊天框后按回车确认、Esc 取消。确认后后端按 dpr 把逻辑坐标换成**物理像素**写进 cfg.ocr_region，提示行显示「框选完成 · 物理 1536×416（逻辑 1024×277）」。「识别一帧」（同 F6）立刻读一次并把结果打到右栏。
  - **提示行**（#ocrNote）：绿色=「范围 W×H · x,y（自动推断）」或「识别到 3 行 · 118 ms」（12 s 后自动回到范围）；琥珀色=「还没框选范围 · 按 F5（或点「框选范围」）」/「识别失败 · 看右栏日志」；过渡态「识别中…」「屏幕上已弹出遮罩：拖好范围按回车，Esc 取消」。
  - **状态行**（卡片最底下）：关着＝「屏幕识别已关 · 按 F7 打开」（常驻模式写「常驻识别已关」）；开着但**没框选＝「还没框选范围 · 按 F5」**（琥珀，后端此时不抓屏、也不兜底抓全屏）；常驻＝「常驻 · 轮询 0.35 s/帧 · F7 开关」；单帧＝「单帧模式 · F6 识别一帧 · F5 改范围」。C 卡空白不是坏了，先看这一行。
- 每卡的右上角小标签是**当前引擎**：本地 + 云端 / 只用本地 / 只用云端 / 屏幕识别；下面一行是**实时句**：上行暗色=原文（带语种），下行亮色=译文。正在识别/翻译/合成的段整块边线变**琥珀色**，翻译出错变红。

**电平**：两条横条，mic（我的麦克风）与 loop（对方声音）。绿色填充实时跳动，右端红色斜纹区是 -20 dB 以上的过载区，竖着的黄色刻度线是当前门限（数值在卡头「门限 A −32.0 / B −24.0 dB」）。超过门限时数值变青色、填充带光晕。

**声音通道**：三个下拉分别选「我的麦克风」「对方听到（VB-Cable）」「对方声音（内录 loopback）」，改完立即下发（后端 cfg 里存设备序号还是设备名都能对上，前端按当前值自适应发回）。↻ 刷新重新扫描设备；**测听**在「对方听到」的设备上放一句测试语音，页面提示「电平条动了就说明通了」。

**回环自测**（设备卡最下面一行）：这是整条链路一次真·闭环体检 —— 后端自己把一句中文合成出来，从「对方听到」的设备播出去，再由 A 链的麦克风真接住。
- 输入框留空 = 用后端默认句；也可以自己填一句中文。
- 点「回环自测」→ `POST /api/inject`，返回后下面那行显示「已播出 x.xx s 音频 · 首包 x ms · 总耗时 x ms · → 设备名」。
- 接着去中间句子表等 3–6 秒，A 链会自己冒一行（中文原文 → 日语译文）；**冒出来就说明麦克风、虚拟声卡、识别、翻译、合成整条路都通**。

**音色**：t1 温柔 / t2 明亮 / t3 最像 / t4 沉稳 四颗胶囊，点一下就切（当前音色高亮，卡头小字显示它的 cos 相似度）。
**语速**滑杆 0.60–1.60（`cfg.speed`，默认 1.00），松手后 120 ms 防抖直接 `POST /api/cfg {"speed":1.20}`，对所有 TTS 生效；试听请求还会额外带上 `speed`，所以立刻能听出快慢。
下面文本框可改试听词、选试听语种、勾「出声」，点**试听**调 `POST /api/tts_test`，回显「合成 xx ms · 首包 xx ms · 音频 x.x s」。

**识别参数**：麦克风门限 / 对面声音门限 / 最短有效语音 / 最长一句 / 句尾停顿确认 / 开口前预录 / 说话时压低原声 / 播放音量 / 播放语速下限 / 播放语速上限，拖动后 120 ms 防抖自动下发（滑杆头数字变黄=正在等后端确认）。

**浮窗**：开关浮窗；再一个开关是「点击穿透」（关=可以按住浮窗任意位置拖动），**复位**让浮窗回到屏幕底部中间；下面三个滑杆调不透明度、缩放、显示行数。

**高级**：工作模式（翻译 / 直通不变声）、识别方式（本地+云端校正 / 只用本地 / 只用云端）、预翻译、回声拦截、双路识别。一般不用动。

## 四、中间：实时句子表

列：时间 / 链 / 原文 / 译文 / 识别 ms / 翻译 ms / 合成 ms / 句长 s / 实时率 / 备注。
- **同一条句子只占一行**：后端对同一 `id` 推多次（识别中→翻译中→合成中→播放中→完成）时，这一行原地刷新并闪一下，不会新增。
- 左侧竖线颜色：A 青、B 紫、C 橙。
- 备注列是状态小标签（合成中/播放中/完成/已校正/已丢弃/出错）+ 说明（已上屏、预合成、草稿、回声）。
- 顶部 4 个筛选（全部 / A 出 / B 入 / C 屏）只影响视图；**「清空」**调 `POST /api/clear`，把后端缓存的句子表和指标一起清零（日志不动），不是只清屏幕；「17 句」是当前行数（上限 400，超出丢掉最旧的）。

## 五、右栏

- **延迟分解**：A、B、C 三条链各一行（识别 `asr_ms` / 翻译 `mt_ms` / 合成 P50，C 链没有合成所以那一格是横杠，识别与翻译都是真数据），下面三行是各链**端到端 P50 / P90**（说完 → 看到/听到），最后一行「起话→开口」= `open_ms`（对方开始说话 → 我这边字幕开始冒出来），数据来自 `/api/metrics` 的 rows，句子落定后自动刷新。端到端可以是负数——意思是这句话还没说完字幕就先出来了。**这几个数一律照后端 `e2e_p50 / e2e_p90` 原样显示，前端不再自己算一遍**（后端的负值也照显，那是最漂亮的情况；`rtf / cps` 只用正值统计）。顶栏那两个大数字同样跟后端走，并且每 2.5 s 轮询一次 `/api/metrics`，所以后端不推 `st` 事件时也不会僵在 0。
- **事件日志**：SSE 的 `log` 事件（信息/警告/错误三色）。最多保留 **200 行**，勾「自动滚底」时自动跟到最新；✕ 清空。
- **C 链·精确标定（物理像素）**：右栏这张卡只干一件事——让你手改 `cfg.ocr_region`。四个输入框是**物理像素**的 x / y / 宽 / 高（等于逻辑坐标 × dpr），点**用这四个数** → `POST /api/cfg {"ocr_region":[x,y,w,h]}`；点**识别一帧**等同左栏那颗（`POST /api/ocr/once`），回显「耗时 xx ms · N 行」+ 每行「原文 → 译文」。**框选入口在左栏 C 卡（或全局 F5）**，比手填四个数快得多。四个数全 0 时 C 链**处于暂停态**（后端不抓屏，日志只提示一次），框好之后单帧/常驻都立刻恢复。

### C 链：单帧识别与框选（F5 / F6 / F7）

整体是一条「**框一次 → 按需读**」的短链，不再默认常驻烧 CPU：

```
F5 / 点「框选范围」        全屏遮罩 → 拖出聊天框 → 回车（Esc 取消）
        │                region_picker.py 只往 stdout 吐一行 {"region":[x,y,w,h]}（逻辑像素）
        ▼                后端 ×dpr 换成物理像素 → 写 cfg.ocr_region → 返回 {ok,region,logical,dpr}
cfg.ocr_region 就位
        │
        ├─ F6 / 点「识别一帧」 → POST /api/ocr/once {} → {ok,ms,lines,items:[{src,dst,box,lang}]}
        │                        前端把结果打进右栏 #ocrOut，句子表多一行 C（橙竖线）
        └─ 切「常驻识别」(cfg.ocr_mode=poll) → 后端每 0.35 s 抓一帧，字幕自己冒
```

- **单帧是默认**（`cfg.ocr_mode="hotkey"`）：后端只准备区域、不起轮询线程，按一次读一次，聊天框不动的时候 CPU 归零。
- **取消**：遮罩里 Esc 直接退出，前端提示「框选已取消」，`cfg.ocr_region` 保持原值不动。
- **没框选就点识别**：后端回 `{"ok":false,"error":"no_region"}`，前端提示行变琥珀「还没框选范围 · 按 F5」，不报错、不卡死。
- **语种**：`cfg.ocr_src` 七档（自动判断/日语/英语/中文/韩语/俄语/其它）。中文那一档的值是 **zh**，韩/俄/泰这类不在本地词表里的走**视觉抄字**（多模态），所以慢 0.6–1.0 s。
- **坐标是物理像素**：这台机器 2560×1600 物理 / 1707×1067 逻辑（dpr 1.5）。遮罩里量到的是逻辑值（比如 1024×277），后端乘完 dpr 存 1536×416。手填右栏四个数时**要填物理的**，不然会框到屏幕外。
- **热键归属**：F5/F6/F7 由后端的全局热键线程（`vrdub/hotkey.py`）处理，网页不抢键；页面上的按钮只是同一套接口的入口，两边行为一致。
- **系统**：后端 pid / 版本 / 运行时长 / 浮窗进程状态 / 麦克风（开或闭 · 是否在采音 · 打不开的原因 · 设备序号）。

## 六、浮窗

- 位置：屏幕**底部居中**（距底部 22 px），无边框、置顶、半透明、圆角，不抢焦点（不会把你游戏里的准心抢走）。
- **拖动**：默认就能拖——按住浮窗**任意位置**拖动，松手即停在原处（`[hud] 拖到: 60 120`），位置记在 `HKCU\\Software\\VRDUB\\hud` 的 `pos` 里，下次起来还在那儿。像第一次 / 想归位时把 `pos` 删掉即可回底部居中。
- **穿透**：**右键浮窗**进入穿透（窗口变成 `WS_EX_TRANSPARENT`、完全收不到鼠标），此时屏幕右上角（浮窗上方 6 px）出现一个 30×30 的半透明**抓手**；按住抓手能把穿透中的浮窗拖走，点它一下或右键它即退出穿透。穿透状态也存在 `passthrough` 键里。
- **首帧定位**：布局第一次算高度时行还没进来（只有 22 px），所以绑定在 `resizeEvent` 上——高度一变就重贴底部，绝不会出现「窗口停在屏幕外只看得到一条边」。
- Qt 的坑（改代码时别踩）：`WA_TransparentForMouseEvents` 会被 Qt 同步进原生 flags，**必须**先 `setAttribute` 再 `setWindowFlags`；反过来写清不掉，切回可拖动会失效。
- 每行：左侧链色条 + 原文（暗）+ 译文（亮，长句自动折行到 2 行）+ 右侧灰色小字 `识别 / 翻译 / 合成 ms · 实时率`；最多显示 `hud_rows` 行，新句子在底部，超出从最旧开始淘汰。
- 同一条句子原地更新；一句 `完成` 后停 20 秒再用 QPropertyAnimation 淡出。
- 说完话的 0.9 秒内底边有一条青色电平条在动。
- 闭麦时右上角红「麦已闭」。20 秒收不到后端 ping 就自己退出；stdin 一断（后端死了）立刻自杀，绝不残留。

## 七、弹幕浮窗（识别结果从屏幕上飘过）

不想盯浮窗的时候用这个：每条字幕像弹幕一样**从右往左匀速划过屏幕**，全屏透明、无边框、置顶、鼠标穿透，玩游戏时完全不挡操作。

- **开关**：左栏「浮窗」卡片里的 **弹幕（译文从屏幕上飘过）**，写的是 `POST /api/cfg {"danmaku":true}`，后端据此起停子进程 `python -m vrdub.danmaku`。系统卡里另有一行「弹幕」显示真实进程状态（`运行中 · pid …` / `已开启（进程未就绪）` / `关闭`）。
- **外观**：铺满主屏的透明窗口，字幕只走**屏幕上方 12% 起的 4 条泳道**（`top_ratio` 默认 0.12），默认最多同屏 4 条，一条穿屏 7 秒（最短 4.5 秒，快慢由时间而不是帧数决定，掉帧也不会忽快忽慢）。每条两行——**译文**（链色、27 px、带 3 px 深色描边）在上、**原文**（暗灰蓝 21 px、带 2.4 px 底衬描边）在下，左侧 4 px 链色竖条 + 圆角半透明底板（`rgba(7,11,19,152)`）+ 1 px 亮边；A 青 `#22d3ee`、B 紫 `#a78bfa`、C 橙 `#fb923c`。4 条泳道互不重叠，泳道没空位时排队（最多 12 条），不会叠成一坨。
- **原地换字**：后端对同一 `id` 先推 `state=asr`（只有原文）再推 `state=done`（带译文），弹幕会**就地把那一行换成译文**，不会新开一条；`state=drop` 直接撤条。
- **性能 / 易读性（重做要点）**：**60 fps**（`QTimer` 16 ms，位移按时间算不按帧累加），每条弹幕的「底板+描边+两行字」**整条预渲染成一张 QPixmap**（`setDevicePixelRatio` 跟着屏幕 DPR 走），每帧只 `drawPixmap` + `setOpacity`，不再逐帧排版；脏矩形只擦「旧位置 ∪ 新位置」两条带；200 ms 淡入 / 300 ms 淡出。主行文字先画 3 px 深色描边再填链色、副行带 2.4 px 底衬，压在亮/花画面上也读得清。窗口 `WindowTransparentForInput + WA_TransparentForMouseEvents + WindowDoesNotAcceptFocus + Tool`，不抢焦点、不进任务栏、不吃鼠标。
- **协议**：和浮窗共用 stdin JSON 行协议（PROTOCOL.md §4），`op` 支持 `seg / cfg / mic / clear / status / ping / quit`。显示参数走 `{"op":"cfg","top_ratio":0.06,"lanes":4,"max_live":4,"dur_s":7.0,"alpha":1.0,"scale":1.0}`（`top_ratio` 默认 0.12），不必进后端 DEFAULTS（后端起来后写一行即可）。`ping` 每 5 s 一次，**20 s 没 ping 自己退出**；stdin 一断（后端进程没了）立刻自杀，实测 **56 ms** 退出、`op=quit` 约 89 ms、stdout 全程 **0 字节**。
- **穿透实证**（`--probe-hit`，win32 实测）：窗口扩展样式 = `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_LAYERED | WS_EX_TOPMOST`；在字幕位置 (800,80) 上 `WindowFromPoint` 返回的是**下面的浏览器窗口**（`passthrough=True`），`GetForegroundWindow` 也仍是浏览器（`steals_focus=False`）——点下去真的落到游戏/浏览器上。
- **截图**：`out/danmaku_a.png`、`out/danmaku_b.png`（**真实桌面** 2560×1600，VRChat 画面之上 6 条弹幕、三条链三色、4 泳道互不重叠、两行清晰可读；两张相差 1.6 s，用来对比位移是否匀速）。喂数据的命令：

```bat
python tools\danmaku_feed.py --src demo --count 8 --gap 900 --hold 14 --top-ratio 0.12 --max-live 6 --lanes 4 --dur-s 7.0 ^
  | python -m vrdub.danmaku --shot-b64 --shot-after 7.0 --quit-after-shot
```

  `--src sse` 直接连真后端 `/api/events`，把 `seg / clear / mic` 转成弹幕协议（断线 1.5 s 重连）。`--shot-b64` 把 PNG 以 base64 打到 stderr（沙箱里子进程写不了盘），外部再落盘。
  **截图必须用 `_grab_physical()`（GDI BitBlt）抓真实屏幕**：`QWidget.grab()` 在 DPR=1.5 下会把预渲染纹理按 1:1 贴进逻辑坐标，截出来的字小一圈还被裁——那是**截图方式**的问题，屏幕上其实是好的（`--shot-window` 才走旧路径）。早前的 `danmaku_shot.png` 是合成背景的版本，已由这两张真实桌面图取代。

## 九、已知限制 / 还没验证的

1. **语速**：协议已加 `cfg.speed`（0.6–1.6，默认 1.0），滑杆直接写 `POST /api/cfg {"speed":1.2}`；`/api/tts_test` 也接受可选 `speed`（不认就自动去掉重试一次，不报错）。`rate_min / rate_max` 是「实时率容差」，和语速是两件事，界面上叫「播放语速下限 / 上限」。
2. **真后端联调范围**：已在 `127.0.0.1:8899` 上验到 —— state 全量回填（设备 / 音色 / 指标 / pid / uptime / mic）、SSE `st / level / seg / log / mic` 正常推送、`seg` 同 id 原地推进 asr→mt→tts→play→done、`POST /api/cfg`（含 `speed`）、`POST /api/clear`、`POST /api/mic`（徽章出现/消失）、`POST /api/inject`（真播出 + A 链接住）。`2026-11-18` 又验到 C 链的单帧与框选：点「识别一帧」→ `POST /api/ocr/once` 返回 `{ok:true,ms:111,lines:1,items:[{src,dst,box,lang}]}`（真截图 OCR + 翻译，111–531 ms 视冷热帧），点「框选范围」→ 遮罩出、回车确认 → `POST /api/region/pick` 返回 `{ok:true,region:[512,592,1536,416],logical:[341,395,1024,277],dpr:1.5}` 并自己写进 `cfg.ocr_region`；取消路径回 `{ok:false,cancel:true}` 提示「框选已取消」。还没验到的：浮窗 `cfg.click=true` 时用真鼠标拖动、后端重启瞬间的 SSE 重连表现、右栏手填四个数后保存的回显（框选已经能把区域写进去，手填只是同一条 `POST /api/cfg`）。
3. **C 链没框选就没数据是预期行为**（口径已改）：之前后端在未标定时兜底抓全屏，把桌面文字全当气泡，一轮实测灌进 55 条噪声段；现在 `_tick` 见到 `ocr_region = [0,0,0,0]` 直接 return，只在日志提示一次。控制台对应地显示「还没框选范围 · 按 F5」（C 卡状态行，琥珀色），不会给你看空表。要看 C 链先框一次：左栏 C 卡「框选范围」、右栏手填四个物理像素、或全局热键 F5。
4. **端到端口径**：`/api/metrics` 的 `e2e_p50 / e2e_p90` 现在是**含负值**的统计（负数＝这句话还没说完字幕/语音就出来了，越快越可能负），前端原样显示、不重算；`rtf / cps` 只用正值。
5. `state.url` 当 base：真后端的 `/api/state` 里其实**没有** `url` 字段（页面和后端同源，相对路径就够），代码两种都兼容——有 `url` 就用它，没有就用同源。端口自动 +1 时只要用新地址打开页面即可。
6. **自测钩子**：地址后面加 `?autoinject=1`，页面在拿到 state 后 2 秒自动点一次「回环自测」（走的就是按钮那条代码路径），用来在无头浏览器里拍「注入后」的截图；平时不用管它。
7. 浮窗截图用 Qt 自己 `grab()` 存（沙箱里子进程写不了盘，PNG 走 stderr base64 再由外部落盘），所以 `hud_shot.png` 是浮窗本体，不含桌面背景。
8. 网页截图走 CDP（`msedge --headless=new --remote-debugging-port=…` + `Page.captureScreenshot`），真等 7–9 秒再拍，所以状态灯是绿的、SSE 是通的；早前用 `--virtual-time-budget` 拍会把定时器快进成「重连中…」，那是拍照方式的问题，不是页面的问题。本机 PySide6 没有 QtWebEngine，没有「程序内嵌网页截图」通道。
9. 窄屏（<1280）上下堆叠、整页滚动（句子表仍占 66vh 独立滚动）；>=1280 三栏，只有句子表 / 日志 / 左栏各自滚，整页不滚。
10. 拍这版截图时为了 A 链接住回环，临时把 `cfg.mic_dev` 切到 24（CABLE Output），拍完已还原 23；`out_on / in_on / ocr_on` 三个开关保持打开。回环自测本身需要「麦克风」选 CABLE Output 才收得到，日常用真麦克风时选自己的设备。
11. 后端会自己重启（换 pid、指标归零），所以截图前要重新 `POST /api/clear` 再喂数据；页面遇到后端重启会自己 2 秒重连，不需要刷新。
12. **弹幕还没由后端真正拉起过**：`cfg.danmaku` 键后端已收下并持久化（63 个 cfg 键之一），但 `app.py` 里起停 `vrdub.danmaku` 的那段是后端侧的活；`state.danmaku` 目前还是 `null`，所以系统卡会显示「已开启（进程未就绪）」。等后端把进程接管后，这一行自动变「运行中 · pid …」。弹幕进程本身已用 `tools/danmaku_feed.py`（demo 与 sse 两种喂法）跑通：6 条弹幕截图、穿透实证、EOF/quit 退出都验过。
13. 弹幕窗口是**全屏置顶**的，多显示器时只铺主屏；想让字幕避开画面中央，在 `op=cfg` 里调 `top_ratio` 或 `lanes`。
14. **浮窗默认能拖了**：老语义（`cfg.click=true` 才可拖）会把窗口切成穿透，用户实际拿到的是「点不动」——现在反过来，默认可交互/可拖，`cfg.click=false` 也不会强制穿透；穿透只能右键 HUD 主动进（再点右上角 30×30 把手取消）。位置与穿透状态存 `HKCU\Software\VRDUB\hud`（`pos` / `passthrough`），删键即回默认（底部居中、不穿透）。
15. **浮窗首帧定位已修**：窗口第一次 `_relayout()` 时行还没进来，高只有 22 px，会把 y 算到屏幕外（实测 493,975 720×22，底边 1181 > 可用区 1019）；现在 `_place_window()` 用 `max(height(), sizeHint())` 兜底，并在 `resizeEvent` 里重贴底部，另外 `_relayout()` 之后补一发 0 ms 的静默重排。实测默认落在 493,791 720×206（底边 997，居中）。
16. **弹幕帧率与文字渲染**：从 30 fps 提到 60 fps 并改成「整条纹理」——底板、描边、两行字一次性画进 QPixmap，每帧只贴图 + 改透明度，字不再逐帧重排。`QWidget.grab()` 在 DPR 1.5 下会截错（字小 + 被裁），自测一律用 GDI BitBlt 抓真实屏幕。
