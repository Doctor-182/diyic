# 给别人用，又不给他主密钥

> 场景：套餐只有一把 API Key，朋友要用 VRChat 变声这一套；不想把自己的主密钥交出去（交出去 = 账号余额 + 全部模型 + 全部账单）。
> 下面三条路按「先试哪个」排序。前两条是阿里云原生能力，第三条是自己搭的网关（仓库里已经能跑）。

---

## 1. 原生多 key：先试这个（零代码）

百炼的 API Key 不是「一个账号只能一把」。官方文档（[获取与配置 API Key](https://help.aliyun.com/zh/model-studio/get-api-key)）写明：

| 项目 | 官方口径 |
| --- | --- |
| 数量上限 | **账号 + 地域维度最多 50 把**，不按业务空间限制 |
| 业务空间 | 单主账号最多 20 个（含默认业务空间）；同一空间内的 key 权限相同 |
| 归属账号 | 可以是主账号，也可以是 **RAM 用户**（`username@<别名>.onaliyun.com`） |
| 自定义权限 | 可限制 **可访问 IP**（最多 20 个地址/网段）+ **可访问模型**（最多 30 个） |
| 临时 key | 最长 1800 秒（适合一次性排障，不适合给朋友） |
| 显示规则 | 新版 key 只在创建成功时完整显示一次，之后列表只有脱敏值 |

**关键认知**：套餐/资源包是按**账号**计的，不是按 key 计的。多建几把 key 是「多几把钥匙开同一扇门」——共用同一份套餐余量，不会各送一份，也不会重复扣费。所以「套餐只能有一个密钥」多半是控制台那把 key 的类型限制，不是账号能力限制。

### 给他建一把的步骤

1. 百炼控制台 → **密钥管理 / API Key** → 右上角选地域（跨地域不能混用）→ **创建 API Key**。
2. 归属账号：**主账号**（想更干净就选 RAM 用户，见第 2 节）。
3. 归属业务空间：**默认业务空间**（除非你要分账）。
4. 权限：**自定义** → 访问模型勾上这三个就够 VRChat 那套：
   `qwen-audio-3.0-asr-flash`（识别）、`qwen3.6-flash`（翻译）、`qwen-audio-3.0-tts-plus`（合成）。
   音色克隆用的是复刻接口，走的是**按量 key**，不在套餐 key 权限里。
5. 访问 IP：填对方的出口 IP（不确定就先留 `0.0.0.0/0`，出问题再收紧）。
6. 确定 → **立刻复制**整串 key（关掉弹窗就再也看不到明文了）。

对方拿到后：控制台右侧「密钥」卡 → 粘贴 → 保存。后端会真打一次 `max_tokens=1` 的 chat 自检，返回「自检正常」才算通，不用重启。

### 这把 key 能干什么、不能干什么

- 能：识别 / 翻译 / 合成 / 生成音色（如果他是按量 key）。
- 不能：看到你的其它 key、你的账单、你的业务空间；你随时可以在控制台删掉它 → **立即失效**。
- 想一把掐死所有外发：删 key 或把 IP 白名单收紧，10 秒内生效。

## 2. RAM 子账号：要「一刀切」和「分账」时用

比多 key 更彻底的一层，适合「朋友是长期用户 / 要单独看他的花费」：

1. RAM 控制台建一个用户（只勾**编程访问**，别给控制台登录）。
2. 给它百炼需要的权限：要么挂系统策略 `AliyunBailianFullAccess`，要么自定义策略包含 `modelstudio:CreateApiKey` 等动作。
3. 回到百炼建 key 时，**归属账号选这个 RAM 用户**。

这样停用/删除 RAM 用户就能连带掐掉他名下那批 key（注意官方那条时间线：2026-03-25 之前由 RAM 用户创建的 key 与用户级联删除；之后创建的不级联，删用户后 key 仍可用，要单独删）。

## 3. 自建子密钥网关：套餐真的只放一把 key 时

`tools\relay.py` —— 你机器上跑一个 HTTP 网关，**主密钥只在本机**，对方拿的是子密钥：

```
  朋友的 VRChat / VRDub ──► 你的网关 127.0.0.1:8787（或局域网/公网地址）
                               │  校验子密钥 → 换成主密钥
                               ▼
                      token-plan.cn-beijing.maas.aliyuncs.com
```

### 起网关

```bat
python tools\relay.py --init     :: 生成 %LOCALAPPDATA%\VRDub\config\relay.json（含一把随机子密钥）
python tools\relay.py            :: 起在 127.0.0.1:8787
python tools\relay.py --print-keys
```

`--init` 会打印子密钥和 admin_key，配置文件长这样（节选）：

```json
{
  "listen": "127.0.0.1:8787",
  "upstream": "https://token-plan.cn-beijing.maas.aliyuncs.com",
  "master_key_env": "DASHSCOPE_TOKENPLAN_KEY",
  "admin_key": "adm-…",
  "keys": [{ "name": "friend", "key": "sub-…", "daily": 2000 }],
  "allow": ["/api/", "/compatible-mode/"],
  "max_body_mb": 32,
  "timeout": 180.0
}
```

主密钥从环境变量或 `%LOCALAPPDATA%\VRDub\config\.env.local` 读（字段名由 `master_key_env` 决定），**不写进这份 json**。

### 对方那边怎么填

VRDub 控制台「密钥」卡：

| 字段 | 值 |
| --- | --- |
| 端点 | `http://<你的地址>:8787` |
| 密钥 | `sub-…`（你发他的那一把） |

或者直接写他自己的 `.env.local`：

```ini
DASHSCOPE_TOKENPLAN_BASE=http://<你的地址>:8787
DASHSCOPE_TOKENPLAN_KEY=sub-…
```

`vrdub/cfg.py` 的 `_host_of()` 与 `vrdub/net.py` 的 `_parse_host()` 已经认 `http://host:port` 这种写法（裸域名仍按 https:443 处理，老配置不受影响）。

### 运维接口

| 路径 | 认证 | 作用 |
| --- | --- | --- |
| `GET /__relay/health` | 免 | `{ok, keys, master, upstream, day}`，探活别用真调用 |
| `GET /__relay/stats` | admin_key 或子密钥 | 每把 key 的 `used / daily`、累计请求/拒绝/错误；子密钥只能看自己 |

### 实测（本机回环，真打百炼，2026-11-25）

| 项 | 经网关 | 直连（历史实测） |
| --- | --- | --- |
| chat 非流式（`qwen3.6-flash`，8 token） | **364 ms** | ~340 ms |
| chat SSE 首块 / 全程 | **292 ms / 344 ms** | ~260 / ~320 ms |

网关本身的开销是**一次进程内转发 + 一轮本地 TCP**，约 +20~25 ms；跨城公网再加 RTT（北京同城 5~15 ms，跨省 30~40 ms）。SSE 是边收边吐（真值表里专门断言了「首块必须早于上游完成」），TTS 不会因为过网关而从「边合成边播」退化成「整段等完」。

### 边界

- **不做 TLS**：公网必须前面挂 Caddy / nginx / frp+tls，否则子密钥和语音内容都是明文。
- **不做用户体系**：只有「子密钥 → 主密钥」替换、白名单、每日配额、记账。
- **单点**：你关机，朋友就断（这是它的属性，不是 bug）。
- **带宽**：识别上传是 wav 转 base64，一次几百 KB 到 1 MB；朋友上行 + 你下行都要算进去。
- **日志**：只记时间/方法/路径/状态/字节数/耗时，不记请求体（音频与文本不进日志）。
- **吊销**：改 `relay.json` 里那条 key 然后重启网关；或用 admin_key 看 `/__relay/stats` 确认是他再用。

### 真值表

`tests\test_relay.py`（7 组 20 项，本地假上游，不花钱）：

```
[1] 认证        无密钥 401 / 错密钥 401 / 白名单外 403
[2] 原样转发    路径+查询原样、上游收到主密钥、体大小一致、响应头保留
[3] SSE         三个事件都到齐、首块 <0.3 s、总耗时覆盖上游节奏（没被攒包）
[4] 体积上限    超 max_body_mb → 413
[5] 配额        daily 用完 → 429 + Retry-After，且 429 不计数
[6] 运维接口    health 免密钥 / stats 需 admin 或子密钥 / 子密钥只看自己
[7] 记账        落盘 JSON 的 used 与请求数一致
```

跑法（项目根）：

```bat
set PYTHONPATH=D:\vrc无言势;D:\vrc无言势\.pylibs
python -m tests.test_relay
```

## 4. 该选哪个

| 你的情况 | 选 |
| --- | --- |
| 只想让朋友能用，不想暴露主密钥 | **第 1 条**：控制台多建一把 key，配 IP + 模型白名单 |
| 想随时「停掉这个人」、想分开看花费 | **第 2 条**：RAM 用户 + 归属该用户的 key |
| 控制台确实不给建第二把 / 要按人限流与审计 | **第 3 条**：`tools\relay.py` |
| 只是想临时排障 | 官方**临时 key**（1800 秒） |
