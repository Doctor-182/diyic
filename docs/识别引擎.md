# 识别引擎

两条链（A 我说→日语、B 对方→中文字幕）各自选引擎，值写在 `asr_engine_a` / `asr_engine_b`：
`hybrid` / `local` / `cloud` / `qwen17` / `qwen06` / `fun`。前三个是「本地 SenseVoice + 云端 qwen-audio-3.0-asr-flash」的组合与单选，后三个是 GGUF 本地大模型档。

## 一、三条路各自的位置

| 路 | 引擎 | 显存 | 单段延迟 | 标点 | 判语种 | 位置 |
|---|---|---|---|---|---|---|
| 快路 | SenseVoice-Small int8（onnxruntime，CPU） | 0 | 79–350 ms（p50 79） | 无 | 靠调用方给 | 一切场景的底座、兜底 |
| 大模型 | GGUF：Qwen3-ASR 1.7B / 0.6B、Fun-ASR-Nano（transcribe.cpp，CUDA/Vulkan） | 805–1441 MiB | p50 133–156 ms，max 828 ms | Qwen 有、Fun 无 | Qwen 有、Fun 无 | 要标点 / 要语种判定 / 要离线 |
| 云端 | qwen-audio-3.0-asr-flash | 0 | 0.34–13.2 s（抖动极大） | 无 | 有（不可靠） | 精修、chatbox 重听、没卡的机器 |

**结论一句话**：SenseVoice 负责「快」，GGUF 负责「准 + 标点 + 语种」，云端只负责「精修与兜底」。云端抖动范围 0.34–13.2 s，不能进 A 链同步路径。

## 二、GGUF 三档（实测数字，不是抄介绍）

| 档 | 模型 | 磁盘 | 显存 | 单段（第 2 次，排除预热） | 载入 |
|---|---|---|---|---|---|
| `qwen17` | Qwen3-ASR-1.7B Q5_K_M | 1447.0 MB | 1441 MiB | 269–484 ms | 4.1 s（首进程 64.6 s 编 PTX） |
| `qwen06` | Qwen3-ASR-0.6B Q8_0 | 811.0 MB | 805 MiB | p50 354 ms | 1.8–4.0 s |
| `fun` | Fun-ASR-Nano-2512 Q8_0 | 850.0 MB | 844 MiB | p50 386 ms（Vulkan 197 ms） | 1.9 s |

- 三档都由 **transcribe.cpp v0.5.0** 跑（ggml，CUDA 或 Vulkan），不是 llama.cpp —— 两套 GGUF 生态互不通，别混。
- 量化代价：Qwen3-ASR 的 LibriSpeech clean WER 在 bf16/f16/q8_0 都是 1.62、q6_k 1.65、**q5_k_m 1.65**、q4_k_m 1.81 ⇒ Q5 基本无损，Q4 开始掉。
- **小模型上 Vulkan 反超 CUDA**：Fun 的 Q8 在 Vulkan 上 197 ms、CUDA 288–414 ms（coopmat2 吃满 tensor core）；1.7B 必须 CUDA（Vulkan 549–607 ms）。
- **CPU 判死**：1.7B 在 24 核 CPU 上 19.6–19.8 s/句（RTF 0.21×），Vulkan 7.4×、CUDA 8.4–10×。

### 3.4 语种提示怎么定（逐段探测，2026-11-27）

Qwen 的第一产物就是 `language X<asr_text>`，钉提示 = 替它做决定。411 段社交语料结构：ja 343 / zh 53 / en **1** / 其它 10 / 空 4 ⇒ 真矛盾是 **ja vs zh**。

钉 ja 的破坏力（实测 232427_zh_A_03）：`这里有别人的声音，我这边有别人的声音。` → `ここに別の人たちの声が聞こえます。`，整句被翻成日语；中文段 CER 50.0%，换 zh 提示后 3.1%。

探测头 = SenseVoice 的语言 token（`LocalASR.lid()`，与主解码并行，正常段 +0 ms）：

| 探测输出 | 精确率 | 召回 | 用途 |
|---|---|---|---|
| zh / yue | **100%** | 75% | 默认开关（`asr_gguf_lid=zh`）就靠它，误报 0 ⇒ 不会把日语段切坏 |
| ja | 99% | 79% | 信它，不切 |
| en | 0–6% | — | **不可信**，只在 `any` 模式认 |
| 空（不吐标签，62/200） | — | — | 当「不确定」，不动 |

按段长：0–2 s 一致 83%、2–4 s 93%、**8 s+ 掉到 61%**（多话轮混语种）⇒ B 链 `max_speech_b` 收到 6 s 能同时改善 LID 与复读。

策略 H（默认）：一律 ja，只有探测明确说 zh/yue 才切。实测 zh 段 50.0% → **3.1%**、ja 段 43.3% **不动**、全量中位 CER 40.0% → **34.3%**。全量按探测路由反而更差（56.5%），因为会把 12/36 日语段判错。

英语：探测头不可信，且 `Yes, I'm going.` 在 ja 提示下会变成 `すごい。`（语种对了、内容翻了）⇒ 脚本判据也抓不到。所以 `any` 模式下补两条：探测说 en 就试；探测没吭声而结果「无假名 + 无汉字 + 拉丁成片」也试一次，重听结果必须过 `lang_ok(en)` 才采用。

## 四、守卫与兜底（改这块别破）

1. **空结果兜底**：GGUF 档出空（解码自重复 / 模型缺失 / 显存不够）→ 用 SenseVoice 重听，engine 记 `local(兜底)`；都不出字才丢段并写 note。
2. **语种漂移守卫**：GGUF 出字后过 `util.lang_ok()`（ja 假名≥15%；zh 汉字≥45% 且假名≤10% 且拉丁≤55%；en 拉丁≥45%；`bare()` 后 <4 字不判）。不对 → SenseVoice 重听，语种对了才换，engine 记 `local(漂移)`；本地也漂 → 保留原结果，**不变成空字幕**。带 language 提示的正常路径下 194 段只剩 2 段漂移（见 3.3）；提示没生效或模型自己改判时这条才是护栏。
3. **标记清理**：`asr_gguf.tidy()` 清 `/sil`、`<sil>`、`[sil]`（`\bsil\b` 边界匹配，`silly` / `すし` 不误伤）。
4. **一次只驻留一个**：`asr_gguf.Resident` 串行带锁，换档先卸旧的（日志「GGUF 切换：卸载 X → 载入 Y」）。两档并存实测出现 12.3 s / 20.8 s 离群延迟，还会吃 2.2–3 GB 显存。
5. **两条链选了不同档**只驻留 B 链那个，并 warn 一句。
6. **chatbox 继承 B 链**：B 链用 GGUF 档时聊天框不再花云端钱重听。
7. **GGUF 档跳过 refine**：自带标点与语种判定，anime-whisper 只会把好的擦掉。

## 五、配置键

| 键 | 默认 | 说明 |
|---|---|---|
| `asr_engine_a` / `asr_engine_b` | `hybrid` | 见开头取值 |
| `asr_gguf_dir` | 空 | 空 = `<程序目录>\models\asr` |
| `asr_gguf_backend` | `cuda` | `cuda` / `vulkan` / `cpu`（小模型 vulkan 更快） |
| `asr_gguf_hint` | `auto` | 是否把语种提示传给模型；`off` 让它自己判 |
| `asr_gguf_lid` | `zh` | 语种探测：`off` 不探 / `zh` 只在明确判出中文时切 / `any` 连 en、ko 也切（见 3.4） |
| `asr_refine` | `auto` | 见 README「精修」 |
| `asr_local_engine` / `asr_engine_map` | 空 / `{}` | 覆盖注册表的自动选档（如 `{"ja": "whisper-anime"}`） |

## 七、坑（踩过的，按这条排查）

1. **CUDA 找库只认 PATH**：`ggml-cuda.dll` 用裸名 `LoadLibraryA("cublas64_12.dll")`，把 DLL 放在它旁边也没用。必须把 `transcribe_cpp_native_cu12\_native` 前置进 PATH（`asr_gguf._env_setup()` 已做）。缺库报 `BackendError: backend error (status 8)`。
2. **PyPI 没有 Windows 版 cublas**（`nvidia-cublas-cu12` win 轮子 0 个），要从 NVIDIA redist 下 `libcublas-windows-x86_64-12.9.1.4-archive.zip`（524 MB）与 `cuda_cudart-windows-x86_64-12.9.79-archive.zip`（3.4 MB）。
3. **PTX 首编 64.6 s**：换驱动/换架构后第一次加载 CUDA 会编 kernel，缓存在 `%LOCALAPPDATA%\NVIDIA\ComputeCache`，第二次新进程只要 0.8–1.2 s。
4. **nvidia-smi 拿不到单进程显存**：Windows WDDM 下 `--query-compute-apps=used_memory` 全是 `[N/A]`，只能看全局或走 PerfMon。
5. **VRChat 有反作弊**：`OpenProcess(PROCESS_VM_READ)` 拿不到，读它的内存要走 `Get-Process` 全表兜底。
6. **bench 口径**：每段跑两次取第二次；三引擎同进程轮转会互相踩显存，必须一次只驻留一个；`Select-Object -First N` 会掐断上游进程，重定向到文件再读。
