# 待修清单（按发现顺序）

## 1. 开关关不干净：本地识别关不掉、翻译关不掉 —— 已修（2026-11-25）

现象（用户原话，m05780）：「那个翻译在我全部停止的时候也不会被关闭。比如说我调为日语，它依旧会在字幕上给我翻译，只是不合成声音而已。」

根因（三条，逐条对应修法）：

| 根因 | 修法 |
| --- | --- |
| A 链没有源头闸：`vrdub/app.py` 采集回调只判 `mic_on`，关 A 链后照样 VAD→ASR→MT→上字幕（不出声而已） | 采集出口加 `a_on = mic_on and asr_on and out_on and mode != "pass"`；B 链同理加 `asr_on` |
| `mode`（trans / pass，直通）在 `vrdub/chains.py` 里一处都没读，选了直通照样翻译照样念 | `StreamChain._link_off()` / `_mt_off()` 把 pass 模式算进判据 |
| 改开关只改 cfg，已进 `_in_q` 的块、已排 `_speak_q` 的句子、播放器缓冲里的音频都继续跑 | `StreamChain.cancel_all(reason)` 三层全清 + 当前段标 `drop`；`App._apply_chain_gates()` 在「真正关掉」那一刻调用它，并清播放器 tts/mic 缓冲 |

新增两个正交总闸（前端「三条链」卡底部「总闸」行，热生效、不落盘）：

- `asr_on`（识别）：关掉两条链都不再识别，麦克风与回环照常采集、电平照显示；
- `mt_on`（翻译）：关掉只出原文——不翻译、不合成、不发聊天框，已排的译文立刻撤掉。

判定顺序：`asr_on` → 链开关 → `mode=pass`。任一命中，采集侧不送、链入口丢弃（第二道保险，记日志「累计 N 段」）、队列里的块取出即作废并留 `drop` 原因。

真值表 `tests/test_gates.py`（7 组 20 项，全过）：

1. A 链关着 → 采集侧送进来也不入队，队列仍空；
2. 识别总闸关着 → A / B 两条链都停；
3. 直通模式 → A 链不翻译不出声，B 链照常（对方仍要中文字幕）；
4. 翻译总闸关着 → 不调 MT、不排 TTS，字幕出原文；
5. 翻译总闸关着 → 收尾不补念尾巴；
6. `cancel_all` → 输入队列 / 当前段 / 待播队列全清，返回作废条数，留 `drop` 原因；
7. 开关关掉之后队列里的块才被取出 → 作废而不是硬跑。

现场日志（`%LOCALAPPDATA%\VRDub\out\srv.log`）：

```
19:25:49 [cfg] A 链已停（麦克风闭着）：在途 0 项作废；麦克风照采、直通照旧
19:25:49 [cfg] B 链已停（B 链开关关着）：在途 0 项作废
19:25:50 [cfg] 配置更新：out_on=True, in_on=True      ← 打开时不砍在途
```

踩过的坑（写下来别再踩）：第一版 `_apply_chain_gates` 是「按当前状态全量清」，翻任何一个开关都会重算一遍，
于是「打开」也砍在途、麦克风本来就闭着时改 `mt_on` 会误报「A 链已停」。改成按**转场方向**判定
（`not out_on and "out_on" in keys` 这种）才是对的。

## 2. B 链空文本静默（done 但 src/dst 都空）—— 已修（2026-11-25）

现象：`/api/state` 里 B 链连续 12 段 `state=done`，但 `src="" dst="" asr_ms=0`；日志只有 `[asr] 云端识别跳过非语音片段（第 3 次）：ali HTTP 400: {}`。用户看不到任何报错，只觉得「对方说话没反应」。

根因：`vrdub/chains.py` 的 `_on_final` 里 `full`（整段识别结果）为空时**没有任何分支**——跳过噪声闸、跳过翻译，直接走到段落收口 `_finish()`，于是空段落被标成 `done`。失败变成了静默。

修法（两道）：

1. **先救**：`engine == "cloud"` 且没出字时，用本地引擎再兜一次（`self.asr.transcribe_fast(audio, lang, e="local")`，不联网）。救回来就照常走，引擎标 `local(兜底)`，日志 `云端没出字，本地兜回 '…'`。只有 `asr_engine_*=cloud` 才会白跑这一趟；`hybrid` 本来就是本地先出字，不会重复。
2. **救不了就说明白**：本地也没字 → 段落标 `drop`，`note` 写「整段没识别出字（cloud，1.50 秒）：云端多半报错了，这段也确实没听出话，已跳过」，并累计 `_empty_n` 每 5 次/每 20 次写一条 `warn` 日志（避免刷屏）。

真值表 `tests/test_empty_asr.py`（4 组 12 项，全过）：

1. 云端空 + 本地有字 → 调了 `cloud → local`，字幕落本地文本，引擎标 `local(兜底)`，不是 drop；
2. 云端空 + 本地也空 → `drop` + note 含「没识别出字」、没走收尾、留了 warn；
3. 本地引擎本来就没字（`engine=local`）→ 只识别一次，不重复兜，仍标 drop；
4. 云端正常出字 → 不多调本地，不 drop。

## 3. A 链「云端优先」默认值

- 实测中文云端 ASR 411/937/1290/1514/2113 ms（n=5，p50 1290），而 `a_cloud_wait=1.0` 只命中 2/5；A 链 e2e p50 1840 ms、p90 2246 ms。
- 建议：语音链路走本地（0.3–0.8 s），文字链路走 chatbox 云端（预算 5 s）。等用户拍板。
## 4. C 链（屏幕 OCR）功能没做完 —— 未完成

现在能做的：`Ctrl+F2` 框选 → 后台截图 → 本地 PP-OCRv4 det + `japan_rec` 识别 → 翻成中文 → 弹幕/浮窗出原文+译文。本机实测单帧 0.3–1.2 s（10 MB 级模型，CPU）。

还没做的（按重要性）：

| 缺口 | 现状 | 要做到什么程度 |
| --- | --- | --- |
| 连续跟随 | 只有手动单帧 + 演示模式假数据；`ocr_src` 有 `window`/`screen` 但没有按变化率调度 | 画面变了才识别（帧差 + 去重指纹已有 `_ocr_engine.fingerprint`），静止时不烧 CPU/不烧钱 |
| 原文浮回原位 | 只有 `ocr_overlay` 的整块浮窗（demo 走假坐标） | 按检测框坐标把译文贴回原文字块上，跟随窗口移动 |
| 多语种 | 只验过日语假名 + 中文 | 韩/俄/泰走视觉抄字（慢 0.6–1.0 s）要真机验证；混排（日英中同屏）要按行判语种，不能整帧一个语言 |
| 遮挡与缩放 | 分辨率/UI 缩放变了要重新框选（F5） | 记住框选时的窗口尺寸，缩放后按比例换算，不用重框 |
| 准确率 | 没有真话语料，全靠几张截图肉眼过 | 录 20 帧真实 VRChat 聊天框截图做回归集，报字准率 |

所以默认 `ocr_on=false`：开关是开的就能用，但不要指望它现在能挂着跑一整晚。

## 5. 音色克隆不完善 —— 未完成

链路本身通了：录音 3–60 s → 下混/24 kHz/峰值归一（增益上限 +30 dB） → 上传复刻 → 轮询训练 → 写进 `voices_custom` 并切到新音色；静音样本在本地就被拦（< −46 dBFS 直接拒，不花钱）。

缺口：

| 缺口 | 说明 |
| --- | --- |
| 样本处理太素 | 只做归一，没有降噪、没有静音裁边、没有多段拼接；环境噪音会原样进模型 |
| 端点限制 | **套餐 key 打复刻接口是 404 `Model not exist.`**（已做端点记忆：404 后本次进程直接转按量），所以必须配按量 key 才能克隆 |
| 没有主观评测 | 克隆出来的音色在长句、情绪句、数字/专有名词上的稳定性，只有零星试听，没有 A/B 打分表 |
| 语速/音高不跟原文 | TTS 侧只有 `rate` 一个粗调，没有「跟着原文语气」的能力 |
| 音色与 B 链无关 | 克隆只作用于 A 链（我说→日语），B 链永远只出字幕，这是设计不是缺口（写在这里免得以后误改） |
