# 待修清单（按发现顺序）

## 1. 开关关不干净：本地识别关不掉、翻译关不掉（2026-11-25 现场反馈）

现象（用户原话）：「本地关不掉…其实翻译也关不掉。打开之后我说话他又会投放到翻译里。如果我开启翻译模式的话。」

已定位的可疑点（尚未改动，等下一轮）：

- 界面上的链路开关只有三个键：`in_on`（A 链）/ `out_on` / `ocr_on`，见 `vrdub/app.py:1246 api_chains()`。
- 真正拦截逻辑只有三处：`vrdub/app.py:337`、`:575`、`:591`，都是 `if not self.cfg.get("in_on", True): return`。
  也就是说关掉 `in_on` 时**已经进入处理流程的那一段不会被撤**，而麦克风采集线程本身还在跑（`mic_on` 是另一个开关，只影响 `bus.set_mic`）。
- B 链走进程回环（`proc_loop`），其启停看的是 `in_on` + `b_*` 条件，不跟 `mic_on` 走，所以「关本地」时回环还在收 VRChat 的声音。
- 翻译模式是 `mode`（`trans` / 直通），`api_cfg` 允许热改，但 `StreamChain._on_final` 在定稿后直接查 `cfg.mode`，改模式不会打断已经在途的段（`vrdub/chains.py` 里几处 `self.cfg.get("mode")`）。
- 结论方向：需要给「关」加一层**硬闸**（采集回调入口统一判定 + 在途段作废），而不是只在三个函数入口 `return`。

## 2. B 链空文本静默（done 但 src/dst 都空）

- 现场：`/api/state` 里 B 链连续 12 段 `state=done` 但 `src="" dst="" asr_ms=0`，日志只有 `[asr] 云端识别跳过非语音片段（第 3 次）：ali HTTP 400: {}`。
- 方向：失败要留 `drop` 状态与原因（`bus.upd(bseg, state="drop", note=...)`），别用 `done` 收尾。

## 3. A 链「云端优先」默认值

- 实测中文云端 ASR 411/937/1290/1514/2113 ms（n=5，p50 1290），而 `a_cloud_wait=1.0` 只命中 2/5；A 链 e2e p50 1840 ms、p90 2246 ms。
- 建议：语音链路走本地（0.3–0.8 s），文字链路走 chatbox 云端（预算 5 s）。等用户拍板。
