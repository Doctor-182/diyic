## 1. C 链（屏幕 OCR）没做完

现在能做的：`Ctrl+F2` 框选 → 后台截图 → 本地 PP-OCRv4 det + `japan_rec` 识别 → 翻成中文 → 弹幕/浮窗出原文+译文。热态单帧识别 34–71 ms、翻译 313–423 ms、端到端 0.4–0.5 s（+ 轮询间隔 0.35 s）；旧文档写的 0.3–1.2 s 是冷启动口径。**默认 `ocr_on=false`。**

| 缺口 | 现状 | 要做到什么程度 |
|---|---|---|
| 框是死的 | `ocr_region` 记的是绝对物理像素（如 `[512, 592, 1536, 416]`），窗口挪动/改分辨率/换 HMD 就得重框 | 记住框选时的窗口尺寸与 DPI，缩放后按比例换算；或自动找聊天框 |
| 连续跟随 | 只有手动单帧；`ocr_src` 有 `window`/`screen` 但没按变化率调度 | 帧差 + 去重指纹（`_ocr_engine.fingerprint` 已有）触发，静止时不烧 CPU |
| 原文浮回原位 | 只有整块浮窗（demo 走假坐标） | 按检测框把译文贴回原文字块，跟随窗口移动 |
| 滚动不跟 | 聊天框一滚，上行气泡挡住识别区 | 跟滚动位置；至少别把 UI 文字当对话 |
| 多语种 | 只验过日语假名 + 中文 | 韩/俄/泰要云端视觉抄字（慢 0.6–1.0 s、按次花钱，先问）；混排按行判语种 |
| 准确率无回归集 | 全靠几张截图肉眼过 | 录 20 帧真实聊天框截图做回归集，报字准率 |

已知代码问题：`vrdub/ocr.py` 里 `if want or (fallback and lines and (self._looks_garbled(lines) or True))` 的 `or True` 让每帧多跑一次全帧 `_vl_boxes`（40–60 ms CPU，不花钱），修掉能省一半。

## 5. 显存看门只管「切之前」，管不了「切之后」

- 预检是静态的一次读数：`fits()` 只看切换那一刻的空闲显存（+ 即将卸掉的旧档），加 256 MiB 余量。
- 如果切完之后 VRChat / 别的程序再涨（进新世界、加载模型、壁纸恢复、录屏开起来），模型已经在显存里，看门不会再拦——那时是驱动自己报 CUDA OOM，表现是识别变空 + 日志里 `CUDA out of memory`。
- 可控的办法：把 `asr_engine_*` 换到 `sv`（0 显存）或 `qwen06`（1225 MiB），或把 VRChat 的画质/模型数降下来。要做「运行中持续监控 + 自动降档」得再想（降档会丢一次识别，且用户可能正说到一半）。
- 另外 `nvidia-smi` 在 WDDM 下拿不到单进程显存（`--query-compute-apps` 全 N/A），所以「我们占了多少」只能靠权重 + 实测 overhead 估，进程级真值只能走 PerfMon/ETW。
